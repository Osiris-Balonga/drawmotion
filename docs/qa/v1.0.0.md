# QA de livraison — DrawMotion v1.0.0

Statut : **à exécuter**, préparation locale `1.0.0-rc.1` du 27 août 2026.
Aucune case ci-dessous n'est validée par les seuls tests automatisés ou par
une approbation générale dans la conversation.

## Identifier la session

- Testeur et date : à renseigner.
- Commit complet testé : à renseigner (`git rev-parse HEAD`).
- URL de preview HTTPS : à renseigner.
- OS, navigateur/version, webcam : à renseigner.
- Résolution, zoom navigateur et luminosité : à renseigner.
- Preuves : liens de captures, PNG et anomalies, sans vidéo personnelle publiée.

Rejouer les parcours gestuels dans Chrome et Edge Windows avec une vraie
webcam. Noter séparément chaque résultat (réussi, échec, non testé) et le
navigateur. Les contrôles locaux du [lot 10](./lot10-local.md) sont une base,
pas les résultats de cette session.

## Parcours manuels

| ID    | Action                                                                                                                             | Résultat attendu                                                                                                                                                                                       |
| ----- | ---------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| QA-01 | Ouvrir la preview dans un profil neuf ; cliquer sur la caméra, refuser, puis réautoriser via le navigateur.                        | Pas de demande avant le clic ; refus expliqué ; reprise possible sans interface bloquée.                                                                                                               |
| QA-02 | Faire les cinq missions sans aide extérieure, puis recharger et utiliser « Revoir le tutoriel ».                                   | Illustrations et instructions compréhensibles ; progression réelle ; fin mémorisée ; tutoriel rejouable. Chronométrer : cible produit moins de deux minutes, noter la durée réelle.                    |
| QA-03 | Tracer lentement puis rapidement une ligne et un cercle en pinçant ; relâcher entre chaque trait.                                  | Début d'encre perceptiblement immédiat, pas de trait fantôme après relâchement, trajectoire cohérente. Noter toute latence gênante ; le temps d'inférence seul ne mesure pas la latence geste → encre. |
| QA-04 | Commencer à gauche, sortir complètement la main du champ, la ramener à droite en pinçant déjà ; répéter cinq fois.                 | Aucun trait ne relie l'ancienne et la nouvelle position. Le nouveau trait part de la position retrouvée.                                                                                               |
| QA-05 | Passer derrière le bord du champ puis revenir ; essayer une lumière plus faible ; arrêter et reprendre la caméra.                  | Pause sûre, « Main non détectée » lisible sous la caméra, reprise sans saut. Pas de promesse de détection si la main n'est plus visible.                                                               |
| QA-06 | Fermer le poing et gommer ; changer la taille de gomme dans le dock puis dans les commandes gestuelles.                            | Effacement effectif, taille synchronisée, outil du dock cohérent, geste non reconnu sans effacement parasite.                                                                                          |
| QA-07 | Garder index et majeur levés (signe paix) pour ouvrir les commandes ; changer couleur, épaisseur et style.                         | Ouverture intentionnelle, grandes cibles sélectionnables sur toute leur surface, paramètres identiques au dock. Une pause entre deux traits n'ouvre pas le menu.                                       |
| QA-08 | Dans le dock, choisir une couleur HEX/RGB et essayer continu, tirets, pointillé ; comparer Libre, Stabilisé et Formes.             | Couleur et style actifs visibles ; prochain trait conforme ; forme régularisée annulable par « Garder mon tracé ». Roue chromatique réservée à souris/tactile/clavier.                                 |
| QA-09 | Dessiner, gommer, annuler puis rétablir ; demander l'effacement complet et l'annuler avant de le confirmer.                        | Historique cohérent ; aucune suppression globale sans confirmation.                                                                                                                                    |
| QA-10 | Zoomer/dézoomer la toile, déplacer avec Espace + glisser, dessiner à nouveau, exporter et ouvrir le PNG.                           | Curseur et encre restent alignés ; PNG conforme au dessin, sans dock, caméra ou pointeur. Vérifier les éléments hors viewport selon le comportement d'export documenté.                                |
| QA-11 | Naviguer au clavier, ouvrir/fermer les réglages, activer la réduction des animations ; tester le zoom natif du navigateur à 200 %. | Focus visible, fermeture possible, contrôles accessibles, indications persistantes lisibles, pas de contenu essentiel inaccessible.                                                                    |
| QA-12 | Tester 1440×900, 1024×768, 782×600 et 640×400 ; tester une tablette réelle en portrait/paysage avec clavier virtuel si disponible. | Caméra dans la fenêtre, dock/zoom utilisables, panneaux défilants sans déplacer toute la page. Ne pas assimiler une émulation desktop à une validation tablette.                                       |
| QA-13 | Dessiner cinq minutes, changer plusieurs fois d'outil, onglet puis caméra en pause.                                                | Pas de gel durable ni accumulation de retard ; caméra libérée en pause. Pas de vidéo, landmarks ou diagnostics envoyés à un tiers dans l'onglet Réseau.                                                |

Pour QA-10, le code actuel exporte le canvas visible avec son zoom et son
déplacement, pas les limites complètes du document. Dézoomer/recentrer avant
d'exporter pour inclure tout le dessin ; faire accepter explicitement cette
limitation avant livraison ou ouvrir un correctif QA-10. Safari, Firefox et macOS
restent « non testés » tant qu'une session dédiée n'a pas été réalisée.
Si une plateforme promise n'est pas disponible, réduire explicitement le
périmètre de compatibilité avec le mainteneur avant livraison.

## Registre des résultats

| ID / navigateur | Résultat   | Observation / preuve / correctif                        |
| --------------- | ---------- | ------------------------------------------------------- |
| QA-01 à QA-13   | Non testés | À remplir par session, une ligne par cas et navigateur. |

Chaque anomalie donne lieu à un correctif ciblé référant son ID, puis à un
nouveau test du cas concerné et des parcours voisins. Une modification du
code après validation invalide les preuves correspondantes.

## Feu vert de livraison

- [ ] Tous les parcours du périmètre annoncé sont réussis et datés.
- [ ] CI distante verte sur le candidat exact, liens des runs joints.
- [ ] `pnpm verify:security-headers <URL-preview-HTTPS>` réussi ; authentification de preview prise en compte sans désactiver la protection par défaut.
- [ ] Licence du projet choisie par le mainteneur ; `LICENSE` ajouté.
- [ ] Notices tierces et conditions des assets finalisées selon [l'inventaire](../THIRD_PARTY.md).
- [ ] Pas de secret, capture personnelle, rapport de test ou build dans les fichiers destinés au dépôt public.
- [ ] Version finale, changelog et limitations relus.
- [ ] Autorisation explicite de fusion, puis promotion `dev -> main`.
- [ ] Production HTTPS, en-têtes et téléchargement PNG vérifiés sur le commit promu.
- [ ] Retour arrière essayé, URLs et résultat consignés selon [la procédure](../RELEASE.md).
- [ ] Autorisation distincte pour publier la release et pour rendre le dépôt public.

Décision du mainteneur, date et SHA : **en attente**.
